El código, por etapas

Etapa 1

Semáforo básico

Primero sin parpadeo: verde, amarillo y rojo, cada uno con su tiempo.

semaforo_basico.ino
const int LED_VERDE    = 4;
const int LED_AMARILLO = 5;
const int LED_ROJO     = 6;

void setup() {
  pinMode(LED_VERDE, OUTPUT);
  pinMode(LED_AMARILLO, OUTPUT);
  pinMode(LED_ROJO, OUTPUT);
}

void loop() {
  // Verde: pasan los carros
  digitalWrite(LED_VERDE, HIGH);
  delay(4000);
  digitalWrite(LED_VERDE, LOW);

  // Amarillo: precaución
  digitalWrite(LED_AMARILLO, HIGH);
  delay(2000);
  digitalWrite(LED_AMARILLO, LOW);

  // Rojo: alto
  digitalWrite(LED_ROJO, HIGH);
  delay(4000);
  digitalWrite(LED_ROJO, LOW);
}
Etapa 2

Con verde parpadeante

Agregamos el parpadeo con un ciclo for, que repite un bloque las veces que le indiquemos.

semaforo.ino
const int LED_VERDE    = 4;
const int LED_AMARILLO = 5;
const int LED_ROJO     = 6;

void setup() {
  pinMode(LED_VERDE, OUTPUT);
  pinMode(LED_AMARILLO, OUTPUT);
  pinMode(LED_ROJO, OUTPUT);
}

void loop() {
  // Verde fijo
  digitalWrite(LED_VERDE, HIGH);
  delay(4000);

  // Verde parpadea 3 veces
  for (int i = 0; i < 3; i++) {
    digitalWrite(LED_VERDE, LOW);
    delay(250);
    digitalWrite(LED_VERDE, HIGH);
    delay(250);
  }
  digitalWrite(LED_VERDE, LOW);

  // Amarillo
  digitalWrite(LED_AMARILLO, HIGH);
  delay(2000);
  digitalWrite(LED_AMARILLO, LOW);

  // Rojo
  digitalWrite(LED_ROJO, HIGH);
  delay(4000);
  digitalWrite(LED_ROJO, LOW);
}

Lo nuevo en esta práctica

  • const int: le pone nombre a un número de pin. Si cambias un LED de pin, solo modificas una línea.
  • pinMode(pin, OUTPUT): el pin va a dar voltaje (salida).
  • digitalWrite(pin, HIGH / LOW): enciende (5 V) o apaga (0 V).
  • delay(ms): espera. 1000 ms = 1 segundo.
  • for: repite un bloque de instrucciones un número fijo de veces.

Cómo se lee el for

for (int i = 0; i < 3; i++)

i = 0: empieza a contar en cero. i < 3: repite mientras i sea menor que 3. i++: suma 1 en cada vuelta.

Resultado: el bloque se ejecuta con i = 0, 1 y 2, o sea 3 veces.

El buzzer

El buzzer (zumbador) convierte una señal eléctrica en sonido. En los kits vienen dos tipos que se ven casi iguales:

ActivoPasivo
Cómo suenaSolo con darle 5 VNecesita una frecuencia
InstruccióndigitalWritetone() / noTone()
TonoUno fijoEl que tú elijas
Por abajoSellado (negro)Se ve la placa verde
Prueba rápida: conecta la pata larga a 5V y la corta a GND. Si suena, es activo. Si no suena o solo hace «clic», es pasivo.

Características

  • Voltaje de trabajo3 – 5 V
  • Corriente≈ 20 – 30 mA
  • PolaridadSí: pata larga a +
  • Frecuencia (activo)≈ 2 300 Hz fija
  • Rango útil (pasivo)≈ 100 – 5 000 Hz

Un buzzer pequeño se puede conectar directo al pin. Para bocinas o alarmas más grandes se necesita un transistor.

El código, por etapas

Etapa 1

Buzzer continuo con el rojo

El buzzer se enciende junto con el LED rojo y se apaga cuando el rojo se apaga. Las dos salidas cambian al mismo tiempo.

semaforo_sonoro.ino
const int LED_VERDE    = 4;
const int LED_AMARILLO = 5;
const int LED_ROJO     = 6;
const int BUZZER       = 8;

void setup() {
  pinMode(LED_VERDE, OUTPUT);
  pinMode(LED_AMARILLO, OUTPUT);
  pinMode(LED_ROJO, OUTPUT);
  pinMode(BUZZER, OUTPUT);
}

void loop() {
  // Verde fijo y parpadeo
  digitalWrite(LED_VERDE, HIGH);
  delay(4000);
  for (int i = 0; i < 3; i++) {
    digitalWrite(LED_VERDE, LOW);
    delay(250);
    digitalWrite(LED_VERDE, HIGH);
    delay(250);
  }
  digitalWrite(LED_VERDE, LOW);

  // Amarillo
  digitalWrite(LED_AMARILLO, HIGH);
  delay(2000);
  digitalWrite(LED_AMARILLO, LOW);

  // Rojo + buzzer al mismo tiempo
  digitalWrite(LED_ROJO, HIGH);
  digitalWrite(BUZZER, HIGH);
  delay(4000);
  digitalWrite(LED_ROJO, LOW);
  digitalWrite(BUZZER, LOW);
}
Etapa 2

Pitido intermitente, como semáforo peatonal

Sustituye solo el bloque del rojo. El for da 8 pitidos de 200 ms con pausas de 300 ms: 8 × 500 ms = 4 segundos, el mismo tiempo que antes.

bloque del rojo
  // Rojo + pitidos intermitentes (4 segundos en total)
  digitalWrite(LED_ROJO, HIGH);
  for (int i = 0; i < 8; i++) {
    digitalWrite(BUZZER, HIGH);
    delay(200);
    digitalWrite(BUZZER, LOW);
    delay(300);
  }
  digitalWrite(LED_ROJO, LOW);
Si tu buzzer es pasivo: cambia digitalWrite(BUZZER, HIGH) por tone(BUZZER, 1500) y digitalWrite(BUZZER, LOW) por noTone(BUZZER). El número 1500 es la frecuencia en hertz: súbelo para un tono más agudo.

Lo nuevo en esta práctica

  • Dos salidas a la vez: dos digitalWrite seguidos se ejecutan tan rápido que el LED y el buzzer cambian juntos.
  • tone(pin, frecuencia): genera un sonido de la frecuencia indicada en un buzzer pasivo.
  • noTone(pin): detiene el sonido.
  • Calcular tiempos: (sonido + pausa) × repeticiones = duración total.

Para pensar

¿Por qué los semáforos peatonales usan pitidos intermitentes y no un sonido continuo?

Porque el ritmo transmite información: muchos cambian a pitidos más rápidos cuando queda poco tiempo para cruzar. Esa misma idea la usaremos en la práctica 3, donde el ritmo indica la distancia.

Cómo leer un diagrama de tiempos

Cada fila es una salida del Arduino. Una barra de color quiere decir que esa salida está en HIGH; si no hay barra, está en LOW.

Se lee de izquierda a derecha. Los números de abajo dicen cuántos milisegundos dura cada tramo: cada uno es un delay() en tu código.

Al llegar al final, el patrón vuelve a empezar, igual que el loop().

Truco: recorre el diagrama tramo por tramo. En cada línea vertical algo cambia: escribe los digitalWrite de lo que cambia ahí y después el delay con el número de abajo.

02

El sensor ultrasónico HC-SR04

Funciona como un murciélago. Uno de sus «ojos» (Trig) lanza un sonido de 40 kHz que los humanos no escuchamos. El sonido rebota en el obstáculo y el otro «ojo» (Echo) lo recibe.

Arduino mide cuántos microsegundos tardó el eco en regresar. Como el sonido viaja a unos 343 m/s (0.0343 cm por microsegundo) y hace el viaje de ida y vuelta:

distancia (cm) = tiempo (µs) × 0.0343 ÷ 2
≈ tiempo (µs) ÷ 58

Ejemplo: si el eco tarda 1160 µs, el obstáculo está a 1160 ÷ 58 = 20 cm.

El tiempo medido incluye ida y regreso; por eso se divide entre 2.

Características

  • Voltaje de trabajo5 V
  • Corriente≈ 15 mA
  • Rango de medición2 – 400 cm
  • Precisión≈ ±3 mm
  • Ángulo de detección≈ 15°
  • Frecuencia40 kHz (ultrasonido)
  • Pulso de disparo10 µs en Trig

Lo que debes saber

Mide mejor superficies planas y duras (pared, cuaderno, caja). Telas, esponjas o superficies inclinadas absorben o desvían el sonido y dan lecturas raras.
En TinkerCAD lo encuentras como Sensor de distancia ultrasónico. Usa el de 4 pines (Trig y Echo separados) para que el código sea el mismo que en el físico.

Etapa 1

¿El sensor mide?

Conecta solo el sensor. Sube este código y abre el Monitor Serie (lupa arriba a la derecha del IDE, a 9600 baudios). Acerca y aleja la mano: el número debe cambiar.

etapa1_medir.ino
const int TRIG = 9;
const int ECHO = 10;

void setup() {
  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
  Serial.begin(9600);        // abre la comunicación con la computadora
}

void loop() {
  // 1. Disparamos un pulso de 10 microsegundos
  digitalWrite(TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);

  // 2. Medimos cuánto tarda en regresar el eco
  long tiempo = pulseIn(ECHO, HIGH);

  // 3. Convertimos el tiempo a centímetros
  long distancia = tiempo / 58;

  Serial.print("Distancia: ");
  Serial.print(distancia);
  Serial.println(" cm");
  delay(200);
}
Comprueba con regla: coloca un cuaderno a 10, 20 y 30 cm del sensor y anota lo que marca el Monitor Serie. Si la diferencia es de 1 o 2 cm, el sensor está bien.
Etapa 2 y 3

Sensor de reversa completo

Agrega los LEDs y el buzzer. El programa mide, decide en qué zona está el obstáculo con if / else if / else y actúa.

sensor_reversa.ino
// ===== Sensor de reversa =====
const int TRIG = 9;
const int ECHO = 10;
const int LED_VERDE    = 4;
const int LED_AMARILLO = 5;
const int LED_ROJO     = 6;
const int BUZZER       = 8;

void setup() {
  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
  pinMode(LED_VERDE, OUTPUT);
  pinMode(LED_AMARILLO, OUTPUT);
  pinMode(LED_ROJO, OUTPUT);
  pinMode(BUZZER, OUTPUT);
  Serial.begin(9600);
}

// Función que mide y regresa la distancia en cm
long medirDistancia() {
  digitalWrite(TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);

  long tiempo = pulseIn(ECHO, HIGH, 30000); // espera máx. 30 ms
  if (tiempo == 0) {
    return 999;           // no regresó eco: no hay obstáculo cerca
  }
  return tiempo / 58;
}

// Apaga los tres LEDs
void apagarLeds() {
  digitalWrite(LED_VERDE, LOW);
  digitalWrite(LED_AMARILLO, LOW);
  digitalWrite(LED_ROJO, LOW);
}

// Un pitido: suena "duracion" ms y calla "pausa" ms
void pitido(int duracion, int pausa) {
  digitalWrite(BUZZER, HIGH);
  delay(duracion);
  digitalWrite(BUZZER, LOW);
  delay(pausa);
}

void loop() {
  long distancia = medirDistancia();
  Serial.print("Distancia: ");
  Serial.print(distancia);
  Serial.println(" cm");

  apagarLeds();

  if (distancia > 50) {
    // Zona segura: verde, sin sonido
    digitalWrite(LED_VERDE, HIGH);
    digitalWrite(BUZZER, LOW);
    delay(100);
  }
  else if (distancia > 30) {
    // Precaución: verde + pitido lento
    digitalWrite(LED_VERDE, HIGH);
    pitido(80, 500);
  }
  else if (distancia > 15) {
    // Cerca: amarillo + pitido rápido
    digitalWrite(LED_AMARILLO, HIGH);
    pitido(80, 150);
  }
  else {
    // ¡Alto!: rojo + tono continuo
    digitalWrite(LED_ROJO, HIGH);
    digitalWrite(BUZZER, HIGH);
    delay(100);
  }
}
Si tu buzzer es pasivo (solo hace «clic» con digitalWrite): cambia digitalWrite(BUZZER, HIGH) por tone(BUZZER, 1500) y digitalWrite(BUZZER, LOW) por noTone(BUZZER).

Lo nuevo en esta práctica

  • Serial.begin() y Serial.println(): Arduino «habla» con la computadora. Sirve para ver qué está midiendo.
  • pulseIn(): mide cuánto tiempo un pin permanece en HIGH, en microsegundos.
  • if / else if / else: el programa toma decisiones según la distancia. Se revisan en orden y solo se ejecuta el primero que se cumple.
  • Funciones propias (medirDistancia(), pitido()): agrupan instrucciones con un nombre para reutilizarlas y que el loop() se lea fácil.

¿Por qué el orden de los if importa?

Si el obstáculo está a 20 cm, el programa pregunta: ¿es mayor que 50? No. ¿Mayor que 30? No. ¿Mayor que 15? Sí → enciende amarillo y deja de preguntar.

Si pusieras primero distancia > 15, a 80 cm también se cumpliría y nunca llegaría a la zona verde. Pregunta siempre de la distancia mayor a la menor.

06

Retos

Fácil

Cambia las distancias de las zonas a 100, 60 y 25 cm, como en una camioneta grande.

Fácil

Haz que en la zona roja el LED también parpadee además del tono.

Medio

Agrega una cuarta zona (5 a 15 cm) con un LED azul o un segundo LED rojo.

Medio

Que la pausa entre pitidos se calcule con la distancia: pitido(80, distancia * 8). Así el ritmo cambia de forma continua, como en un carro real.

Reto

Agrega un botón de «marcha atrás»: el sensor solo funciona mientras el botón esté presionado, igual que en el carro cuando metes reversa.

Preguntas para cerrar

  1. Si el eco tarda 2900 µs, ¿a cuántos centímetros está el obstáculo?
  2. ¿Por qué se divide entre 2 al calcular la distancia?
  3. ¿Qué pasaría si el sensor apunta a una almohada? ¿Por qué?
  4. ¿Qué otra máquina o proceso industrial podría usar este mismo sensor? (Ejemplos: medir el nivel de un tanque, contar cajas en una banda, detectar personas en una puerta automática.)
