El código, por etapas

Etapa 1

Semáforo básico

Primero sin parpadeo: verde, amarillo y rojo, cada uno con su tiempo.

semaforo_basico.ino
const int LED_VERDE    = 4;
const int LED_AMARILLO = 5;
const int LED_ROJO     = 6;

void setup() {
  pinMode(LED_VERDE, OUTPUT);
  pinMode(LED_AMARILLO, OUTPUT);
  pinMode(LED_ROJO, OUTPUT);
}

void loop() {
  // Verde: pasan los carros
  digitalWrite(LED_VERDE, HIGH);
  delay(4000);
  digitalWrite(LED_VERDE, LOW);

  // Amarillo: precaución
  digitalWrite(LED_AMARILLO, HIGH);
  delay(2000);
  digitalWrite(LED_AMARILLO, LOW);

  // Rojo: alto
  digitalWrite(LED_ROJO, HIGH);
  delay(4000);
  digitalWrite(LED_ROJO, LOW);
}
Etapa 2

Con verde parpadeante

Agregamos el parpadeo: apagar, esperar, encender, esperar… tres veces. Cada parpadeo son las mismas cuatro líneas, escritas una vez por cada parpadeo.

semaforo.ino
const int LED_VERDE    = 4;
const int LED_AMARILLO = 5;
const int LED_ROJO     = 6;

void setup() {
  pinMode(LED_VERDE, OUTPUT);
  pinMode(LED_AMARILLO, OUTPUT);
  pinMode(LED_ROJO, OUTPUT);
}

void loop() {
  // Verde fijo
  digitalWrite(LED_VERDE, HIGH);
  delay(4000);

  // Verde parpadea: 1.ª vez
  digitalWrite(LED_VERDE, LOW);
  delay(250);
  digitalWrite(LED_VERDE, HIGH);
  delay(250);

  // 2.ª vez
  digitalWrite(LED_VERDE, LOW);
  delay(250);
  digitalWrite(LED_VERDE, HIGH);
  delay(250);

  // 3.ª vez
  digitalWrite(LED_VERDE, LOW);
  delay(250);
  digitalWrite(LED_VERDE, HIGH);
  delay(250);

  digitalWrite(LED_VERDE, LOW);   // apagamos el verde antes del amarillo

  // Amarillo
  digitalWrite(LED_AMARILLO, HIGH);
  delay(2000);
  digitalWrite(LED_AMARILLO, LOW);

  // Rojo
  digitalWrite(LED_ROJO, HIGH);
  delay(4000);
  digitalWrite(LED_ROJO, LOW);
}

Lo nuevo en esta práctica

  • const int: le pone nombre a un número de pin. Si cambias un LED de pin, solo modificas una línea.
  • pinMode(pin, OUTPUT): el pin va a dar voltaje (salida).
  • digitalWrite(pin, HIGH / LOW): enciende (5 V) o apaga (0 V).
  • delay(ms): espera. 1000 ms = 1 segundo.
  • // comentario: todo lo que va después de // es una nota para personas. El Arduino lo ignora.

Cómo se arma un parpadeo

Un parpadeo son 4 líneas: apagar, esperar 250 ms, encender, esperar 250 ms. En total, medio segundo.

Para que parpadee 3 veces, esas 4 líneas se escriben 3 veces, una debajo de otra. El Arduino las ejecuta en orden, de arriba hacia abajo.

Al final apagamos el verde, porque si no se quedaría encendido junto con el amarillo.

El código, por etapas

Etapa 1

Buzzer continuo con el rojo

El buzzer se enciende junto con el LED rojo y se apaga cuando el rojo se apaga. Las dos salidas cambian al mismo tiempo.

semaforo_sonoro.ino
const int LED_VERDE    = 4;
const int LED_AMARILLO = 5;
const int LED_ROJO     = 6;
const int BUZZER       = 8;

void setup() {
  pinMode(LED_VERDE, OUTPUT);
  pinMode(LED_AMARILLO, OUTPUT);
  pinMode(LED_ROJO, OUTPUT);
  pinMode(BUZZER, OUTPUT);
}

void loop() {
  // Verde fijo
  digitalWrite(LED_VERDE, HIGH);
  delay(4000);

  // Verde parpadea 3 veces (igual que en la práctica 1)
  digitalWrite(LED_VERDE, LOW);
  delay(250);
  digitalWrite(LED_VERDE, HIGH);
  delay(250);
  digitalWrite(LED_VERDE, LOW);
  delay(250);
  digitalWrite(LED_VERDE, HIGH);
  delay(250);
  digitalWrite(LED_VERDE, LOW);
  delay(250);
  digitalWrite(LED_VERDE, HIGH);
  delay(250);
  digitalWrite(LED_VERDE, LOW);

  // Amarillo
  digitalWrite(LED_AMARILLO, HIGH);
  delay(2000);
  digitalWrite(LED_AMARILLO, LOW);

  // Rojo + buzzer al mismo tiempo
  digitalWrite(LED_ROJO, HIGH);
  digitalWrite(BUZZER, HIGH);
  delay(4000);
  digitalWrite(LED_ROJO, LOW);
  digitalWrite(BUZZER, LOW);
}
Etapa 2

Pitido intermitente, como semáforo peatonal

Sustituye solo el bloque del rojo. Son 4 pitidos: cada uno suena 500 ms y calla 500 ms. 4 × 1000 ms = 4 segundos, el mismo tiempo que antes.

bloque del rojo
  // Rojo + pitidos intermitentes (4 segundos en total)
  digitalWrite(LED_ROJO, HIGH);

  // pitido 1
  digitalWrite(BUZZER, HIGH);
  delay(500);
  digitalWrite(BUZZER, LOW);
  delay(500);

  // pitido 2
  digitalWrite(BUZZER, HIGH);
  delay(500);
  digitalWrite(BUZZER, LOW);
  delay(500);

  // pitido 3
  digitalWrite(BUZZER, HIGH);
  delay(500);
  digitalWrite(BUZZER, LOW);
  delay(500);

  // pitido 4
  digitalWrite(BUZZER, HIGH);
  delay(500);
  digitalWrite(BUZZER, LOW);
  delay(500);

  digitalWrite(LED_ROJO, LOW);
Si tu buzzer es pasivo: cambia digitalWrite(BUZZER, HIGH) por tone(BUZZER, 1500) y digitalWrite(BUZZER, LOW) por noTone(BUZZER). El número 1500 es la frecuencia en hertz: súbelo para un tono más agudo.

Lo nuevo en esta práctica

  • Dos salidas a la vez: dos digitalWrite seguidos se ejecutan tan rápido que el LED y el buzzer cambian juntos.
  • tone(pin, frecuencia): genera un sonido de la frecuencia indicada en un buzzer pasivo.
  • noTone(pin): detiene el sonido.
  • Calcular tiempos: (sonido + pausa) × número de pitidos = duración total.

Para pensar

¿Por qué los semáforos peatonales usan pitidos intermitentes y no un sonido continuo?

Porque el ritmo transmite información: muchos cambian a pitidos más rápidos cuando queda poco tiempo para cruzar. Esa misma idea la usaremos en la práctica 3, donde el ritmo indica la distancia.

Cómo leer un diagrama de tiempos

Cada fila es una salida del Arduino. Una barra de color quiere decir que esa salida está en HIGH; si no hay barra, está en LOW.

Se lee de izquierda a derecha. Los números de abajo dicen cuántos milisegundos dura cada tramo: cada uno es un delay() en tu código.

Al llegar al final, el patrón vuelve a empezar, igual que el loop().

Truco: recorre el diagrama tramo por tramo. En cada línea vertical algo cambia: escribe los digitalWrite de lo que cambia ahí y después el delay con el número de abajo.

02

El sensor ultrasónico HC-SR04

Funciona como un murciélago. Uno de sus «ojos» (Trig) lanza un sonido de 40 kHz que los humanos no escuchamos. El sonido rebota en el obstáculo y el otro «ojo» (Echo) lo recibe.

Arduino mide cuántos microsegundos tardó el eco en regresar. Como el sonido viaja a unos 343 m/s (0.0343 cm por microsegundo) y hace el viaje de ida y vuelta:

distancia (cm) = tiempo (µs) × 0.0343 ÷ 2
≈ tiempo (µs) ÷ 58

Ejemplo: si el eco tarda 1160 µs, el obstáculo está a 1160 ÷ 58 = 20 cm.

El tiempo medido incluye ida y regreso; por eso se divide entre 2.

Características

  • Voltaje de trabajo5 V
  • Corriente≈ 15 mA
  • Rango de medición2 – 400 cm
  • Precisión≈ ±3 mm
  • Ángulo de detección≈ 15°
  • Frecuencia40 kHz (ultrasonido)
  • Pulso de disparo10 µs en Trig

Etapa 2 y 3

Sensor de reversa completo

Agrega los LEDs y el buzzer. El programa mide, decide en qué zona está el obstáculo con if / else if / else y actúa.

sensor_reversa.ino
// ===== Sensor de reversa =====

// Pines del sensor ultrasónico
const int TRIG = 9;
const int ECHO = 10;

// Pines de los LEDs y el buzzer
const int LED_VERDE    = 4;
const int LED_AMARILLO = 5;
const int LED_ROJO     = 6;
const int BUZZER       = 8;

void setup() {
  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
  pinMode(LED_VERDE, OUTPUT);
  pinMode(LED_AMARILLO, OUTPUT);
  pinMode(LED_ROJO, OUTPUT);
  pinMode(BUZZER, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  // 1. El sensor manda un sonido
  digitalWrite(TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);

  // 2. Medimos cuánto tarda en regresar el eco
  long tiempo = pulseIn(ECHO, HIGH, 30000);

  // 3. Convertimos el tiempo a centímetros
  long distancia = tiempo / 58;

  // Si el eco no regresó, no hay nada cerca
  if (tiempo == 0) {
    distancia = 999;
  }

  // 4. Mostramos la distancia en el monitor serie
  Serial.print("Distancia: ");
  Serial.print(distancia);
  Serial.println(" cm");

  // 5. Apagamos todo antes de decidir
  digitalWrite(LED_VERDE, LOW);
  digitalWrite(LED_AMARILLO, LOW);
  digitalWrite(LED_ROJO, LOW);
  digitalWrite(BUZZER, LOW);

  // 6. Decidimos qué hacer según la distancia
  if (distancia > 30) {
    // Lejos: verde, sin sonido
    digitalWrite(LED_VERDE, HIGH);
    delay(100);
  }
  else if (distancia > 20) {
    // Precaución: verde y pitido lento
    digitalWrite(LED_VERDE, HIGH);
    digitalWrite(BUZZER, HIGH);
    delay(80);
    digitalWrite(BUZZER, LOW);
    delay(500);
  }
  else if (distancia > 15) {
    // Cerca: amarillo y pitido rápido
    digitalWrite(LED_AMARILLO, HIGH);
    digitalWrite(BUZZER, HIGH);
    delay(80);
    digitalWrite(BUZZER, LOW);
    delay(150);
  }
  else {
    // ¡Alto!: rojo y sonido continuo
    digitalWrite(LED_ROJO, HIGH);
    digitalWrite(BUZZER, HIGH);
    delay(100);
  }
}
Si tu buzzer es pasivo (solo hace «clic» con digitalWrite): cambia digitalWrite(BUZZER, HIGH) por tone(BUZZER, 1500) y digitalWrite(BUZZER, LOW) por noTone(BUZZER).

Lo nuevo en esta práctica

  • Serial.begin() y Serial.println(): Arduino «habla» con la computadora. Sirve para ver qué está midiendo.
  • pulseIn(): mide cuánto tiempo un pin permanece en HIGH, en microsegundos.
  • if / else if / else: el programa toma decisiones según la distancia. Se revisan en orden y solo se ejecuta el primero que se cumple.
  • El caso 999: si el eco no regresa (no hay nada enfrente), pulseIn() da 0. Entonces ponemos distancia = 999 para que el programa lo trate como «muy lejos» y prenda el verde.

¿Por qué el orden de los if importa?

Si el obstáculo está a 18 cm, el programa pregunta: ¿es mayor que 30? No. ¿Mayor que 20? No. ¿Mayor que 15? Sí → enciende amarillo y deja de preguntar.

Si pusieras primero distancia > 15, a 80 cm también se cumpliría y nunca llegaría a la zona verde. Pregunta siempre de la distancia mayor a la menor.

El servomotor

Un motor normal gira sin parar mientras le llega energía. Un servomotor es distinto: tú le dices un ángulo entre 0° y 180°, va hacia allá y se queda firme en esa posición, aunque intentes moverlo con la mano.

Por dentro tiene un motor pequeño, unos engranes que le dan fuerza, un potenciómetro que mide en qué posición está el eje y un circuito que compara: «¿ya llegué al ángulo que me pidieron?». Si no, mueve el motor hasta llegar.

El Arduino le dice el ángulo con un pulso que se repite cada 20 ms: un pulso corto lo lleva a 0° y uno largo a 180°. No tienes que calcular nada; la librería Servo lo hace por ti. Tú solo escribes miServo.write(90).

Los tres cables

Café GND (−) Rojo 5 V (+) Naranja señal

En otras marcas los colores pueden ser negro, rojo y blanco o amarillo. La regla es la misma: el oscuro va a GND, el rojo al positivo y el claro a la señal.

Micro servo SG90

  • Voltaje de trabajo4.8 – 6 V
  • Rango de giro0° – 180°
  • Velocidad≈ 0.1 s por cada 60°
  • Fuerza (torque)≈ 1.8 kg·cm
  • Corriente al moversehasta ≈ 250 mA

No lo fuerces con la mano cuando esté encendido: los engranes son de plástico y se barren. Si zumba en 0° o en 180°, está chocando con su tope; usa 5° o 175°.

pluma_estacionamiento.ino
// ===== Pluma de estacionamiento =====
#include <Servo.h>

const int TRIG = 9;       // sensor de costado, mirando hacia el carril
const int ECHO = 10;
const int LED_VERDE    = 4;
const int LED_AMARILLO = 5;
const int LED_ROJO     = 6;
const int BUZZER       = 8;

const int ABAJO  = 0;    // pluma cerrada
const int ARRIBA = 90;   // pluma abierta

Servo pluma;

void setup() {
  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
  pinMode(LED_VERDE, OUTPUT);
  pinMode(LED_AMARILLO, OUTPUT);
  pinMode(LED_ROJO, OUTPUT);
  pinMode(BUZZER, OUTPUT);
  Serial.begin(9600);

  pluma.attach(2);
  pluma.write(ABAJO);              // al encender, la pluma empieza cerrada
  digitalWrite(LED_ROJO, HIGH);    // y el semáforo en rojo
}

void loop() {
  // Medimos la distancia, igual que en la práctica 4
  digitalWrite(TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);

  long tiempo = pulseIn(ECHO, HIGH, 30000);
  long distancia = tiempo / 58;

  // Si el eco no regresó, no hay nada enfrente
  if (tiempo == 0) {
    distancia = 999;
  }

  Serial.print("Distancia: ");
  Serial.print(distancia);
  Serial.println(" cm");

  if (distancia < 15) {   // hay un carro frente al sensor
    // 1. Llegó un carro: amarillo durante 1 segundo
    digitalWrite(LED_ROJO, LOW);
    digitalWrite(LED_AMARILLO, HIGH);
    delay(1000);
    digitalWrite(LED_AMARILLO, LOW);

    // 2. Verde y la pluma sube de 0 a 90 grados
    digitalWrite(LED_VERDE, HIGH);
    pluma.write(ARRIBA);
    delay(3000);                   // el carro tiene 3 segundos para pasar

    // 3. Rojo y la pluma baja
    digitalWrite(LED_VERDE, LOW);
    digitalWrite(LED_ROJO, HIGH);
    pluma.write(ABAJO);
    delay(1000);                   // tiempo para que la pluma termine de bajar
  }

  delay(100);
}
Mientras no haya carro, el if no se cumple y no cambia nada: el rojo sigue encendido y la pluma sigue abajo. Cuando el sensor ve un carro a menos de 15 cm, empieza la secuencia: amarillo 1 segundo, verde con la pluma arriba 3 segundos, y de nuevo rojo con la pluma abajo.

Lo nuevo en esta práctica

  • #include <Servo.h> agrega la librería de servos: código que ya viene con el Arduino IDE.
  • Servo pluma; crea un servo llamado pluma.
  • pluma.attach(2) le dice en qué pin está su cable de señal.
  • pluma.write(90) lo mueve a 90 grados y ahí se queda.
  • const int ARRIBA = 90; le pone nombre a un ángulo, igual que hicimos con los pines.

¿Por qué no hay else?

Si no hay carro, no hay nada que cambiar: la pluma ya está abajo y el rojo ya está encendido desde el setup() o desde el final de la última secuencia. Por eso solo usamos if.

Y mientras la pluma está arriba, el Arduino está «dormido» en los delay(): no mide nada hasta que termina la secuencia y el loop() vuelve a empezar.

Un motor normal gira sin parar mientras le llega energía. Un servomotor es distinto: tú le dices un ángulo entre 0° y 180°, va hacia allá y se queda firme en esa posición, aunque intentes moverlo con la mano.

Por dentro tiene un motor pequeño, unos engranes que le dan fuerza, un potenciómetro que mide en qué posición está el eje y un circuito que compara: «¿ya llegué al ángulo que me pidieron?». Si no, mueve el motor hasta llegar.

El Arduino le dice el ángulo con un pulso que se repite cada 20 ms: un pulso corto lo lleva a 0° y uno largo a 180°. No tienes que calcular nada; la librería Servo lo hace por ti. Tú solo escribes miServo.write(90).

El display de 7 segmentos

Es el mismo display de los relojes digitales y las calculadoras: siete segmentos que se nombran con letras de la a a la g, empezando arriba y girando como las manecillas del reloj. La g es la del centro.

Para formar un número decides qué segmentos se ven. El 1 solo usa b y c; el 8 usa los siete.

Si escribimos SI cuando el segmento se ve y NO cuando se esconde, cada número se convierte en una fila de siete respuestas. Esa fila es justo lo que vamos a escribir en el programa.

Cómo se arma el display

El display tiene tres capas, de atrás hacia adelante:

  1. Tablero trasero (cartón grueso o MDF de 3 mm, de unos 25 × 30 cm) pintado de negro. Ahí se pegan los 7 servos con silicón, con el eje mirando hacia el frente.
  2. Las 7 tiras de foami o cartulina de color brillante, de unos 10 × 1.6 cm. Cada una se pega por un extremo al brazo de su servo, de modo que el eje queda en la punta de la tira.
  3. La máscara: otro cartón negro con las 7 ventanas recortadas, más cortas que las tiras (unos 6.5 cm). Va al frente, separada unos 3 cm con palitos o tapas para que las tiras giren detrás.

Con el servo en 90° la tira queda detrás de su ventana. En 0° gira un cuarto de vuelta hacia afuera del número y queda escondida detrás de la máscara.

La línea punteada es la parte de la tira que queda detrás de la máscara. El círculo es el eje del servo.

Antes de pegar nada: acomoda los servos sobre el tablero con las tiras puestas y gíralas con la mano para comprobar que no choquen entre sí. Orienta el cuerpo de cada servo hacia afuera del número.

Paso 1 · Un solo servo (etapas 1 y 2)

Un servo sin nada encima se puede alimentar desde el Arduino: café a GND, rojo a 5V y naranja al pin 2. La línea punteada marca hacia dónde apunta el brazo en 0° y en 180°.

Paso 2 · Los 7 servos con fuente externa (etapas 3 y 4)

Los servos toman la energía de la fuente; el Arduino solo les manda la señal. El cable de GND del Arduino al riel − es obligatorio: sin tierra común los servos no entienden la señal.

Nunca conectes los 7 servos al pin 5V del Arduino. Al moverse juntos piden hasta 7 × 250 mA ≈ 1.75 A y el USB solo da 500 mA: el Arduino se reinicia o se desconecta de la compu.
No unas el + de la fuente con el pin 5V del Arduino. Solo se unen las tierras (GND). Revisa también la polaridad del capacitor: la franja va al riel −.

El código, por etapas

Las etapas 1 y 2 son un repaso de la práctica 5 con un solo servo; si ya las dominas, pasa directo a la etapa 3. La 3 y la 4 se hacen con el display armado y la fuente externa.

Etapa 1

Mover un servo a tres posiciones

Conecta un solo servo: naranja al pin 2, rojo al 5V y café al GND del Arduino. Un servo sin carga sí lo aguanta el USB; con más servos ya no.

etapa1_servo.ino
#include <Servo.h>     // librería para servos (ya viene con el IDE)

Servo miServo;          // creamos un servo y le ponemos nombre

void setup() {
  miServo.attach(2);    // la señal (cable naranja) va al pin 2
}

void loop() {
  miServo.write(0);     // ve a 0 grados
  delay(1000);
  miServo.write(90);    // ve a 90 grados
  delay(1000);
  miServo.write(180);   // ve a 180 grados
  delay(1000);
  miServo.write(90);
  delay(1000);
}
Ponle el brazo de una punta al servo para ver bien hacia dónde apunta. Compara las posiciones con el explorador de la sección 02.
Etapa 2

Movimiento por pasos

Con write(180) el servo salta de golpe, a toda velocidad. Si en lugar de eso le pedimos el camino en pasos pequeños, con una pausa entre cada uno, se mueve más despacio. Cambia solo el loop():

etapa2_pasos.ino · loop()
void loop() {
  // de ida: de 0 a 180 en pasos de 30 grados
  miServo.write(0);
  delay(300);
  miServo.write(30);
  delay(300);
  miServo.write(60);
  delay(300);
  miServo.write(90);
  delay(300);
  miServo.write(120);
  delay(300);
  miServo.write(150);
  delay(300);
  miServo.write(180);
  delay(1000);       // pausa larga al llegar

  // de regreso: de 180 a 0 de un solo salto
  miServo.write(0);
  delay(1000);
}

Observa la diferencia: de ida el brazo avanza poco a poco; de regreso salta de golpe. Prueba cambiar los delay(300) por delay(100). ¿Qué pasa con la velocidad?

Etapa 3

Siete servos: alinear los brazos

Conecta los 7 servos con la fuente externa, todavía sin los brazos puestos. Este programa crea un servo para cada segmento (segA, segB…) y los manda a todos al ángulo que escribas en ANGULO.

Antes de conectar la fuente: pide al docente que revise el cableado. Los cables rojos de los servos van al riel + de la fuente, nunca al 5V del Arduino.
etapa3_alinear.ino
#include <Servo.h>

// Un servo para cada segmento del display
Servo segA;
Servo segB;
Servo segC;
Servo segD;
Servo segE;
Servo segF;
Servo segG;

// Primero súbelo con 0. Después cámbialo a 90 y súbelo otra vez.
const int ANGULO = 0;

void setup() {
  // Movemos los servos uno por uno, con una pausa entre cada uno
  segA.attach(2);
  segA.write(ANGULO);
  delay(200);

  segB.attach(3);
  segB.write(ANGULO);
  delay(200);

  segC.attach(4);
  segC.write(ANGULO);
  delay(200);

  segD.attach(5);
  segD.write(ANGULO);
  delay(200);

  segE.attach(6);
  segE.write(ANGULO);
  delay(200);

  segF.attach(7);
  segF.write(ANGULO);
  delay(200);

  segG.attach(8);
  segG.write(ANGULO);
  delay(200);
}

void loop() {
  // vacío: los servos se quedan quietos en su ángulo
}
  1. Sube el programa con ANGULO = 0. Los servos se mueven a 0° uno por uno.
  2. Coloca cada brazo con su tira apuntando hacia afuera del número, escondida detrás de la máscara.
  3. Cambia la línea a ANGULO = 90 y súbelo otra vez. Todas las tiras deben quedar detrás de sus ventanas.
  4. Si una tira queda chueca, quita el brazo y recolócalo un diente antes o después. Si gira hacia el lado equivocado, pon ese servo en el otro extremo del segmento.
¿Por qué la pausa de 200 ms? Si los 7 servos arrancan al mismo tiempo piden mucha corriente de golpe. Moviéndolos uno por uno, la fuente trabaja tranquila.
Etapa 4

El display del 0 al 9

Ya con los brazos alineados, hacemos una función llamada mostrar() que recibe 7 valores, uno para cada segmento, en orden de la a a la g. Cada valor es SI (la tira se ve) o NO (se esconde). Así cada número queda escrito en una sola línea, igual que en la tabla de la sección 03.

display_servos.ino
// ===== Display de 7 segmentos con servos =====
#include <Servo.h>

// Un servo para cada segmento
Servo segA;
Servo segB;
Servo segC;
Servo segD;
Servo segE;
Servo segF;
Servo segG;

// Los dos ángulos que usamos
const int SI = 90;   // la tira se ve
const int NO = 0;    // la tira se esconde

void setup() {
  segA.attach(2);
  segB.attach(3);
  segC.attach(4);
  segD.attach(5);
  segE.attach(6);
  segF.attach(7);
  segG.attach(8);
}

// Mueve los 7 servos. Recibe SI o NO para cada segmento: a, b, c, d, e, f, g
void mostrar(int a, int b, int c, int d, int e, int f, int g) {
  segA.write(a);
  delay(60);
  segB.write(b);
  delay(60);
  segC.write(c);
  delay(60);
  segD.write(d);
  delay(60);
  segE.write(e);
  delay(60);
  segF.write(f);
  delay(60);
  segG.write(g);
  delay(60);
}

void loop() {
  //      a   b   c   d   e   f   g
  mostrar(SI, SI, SI, SI, SI, SI, NO);   // número 0
  delay(1500);
  mostrar(NO, SI, SI, NO, NO, NO, NO);   // número 1
  delay(1500);
  mostrar(SI, SI, NO, SI, SI, NO, SI);   // número 2
  delay(1500);
  mostrar(SI, SI, SI, SI, NO, NO, SI);   // número 3
  delay(1500);
  mostrar(NO, SI, SI, NO, NO, SI, SI);   // número 4
  delay(1500);
  mostrar(SI, NO, SI, SI, NO, SI, SI);   // número 5
  delay(1500);
  mostrar(SI, NO, SI, SI, SI, SI, SI);   // número 6
  delay(1500);
  mostrar(SI, SI, SI, NO, NO, NO, NO);   // número 7
  delay(1500);
  mostrar(SI, SI, SI, SI, SI, SI, SI);   // número 8
  delay(1500);
  mostrar(SI, SI, SI, SI, NO, SI, SI);   // número 9
  delay(1500);
}
Escríbelo por partes: primero solo el 0 y el 1 en el loop(). Cuando funcionen, agrega los demás números de uno en uno.

Lo nuevo en esta práctica

  • #include <Servo.h> agrega una librería: código que ya viene con el Arduino IDE y que nos ahorra el trabajo de generar los pulsos.
  • Servo segA; crea un servo llamado segA. Hicimos siete, uno por segmento.
  • attach(2) le dice al servo en qué pin está su cable de señal.
  • write(90) lo mueve a 90 grados.
  • Una función que recibe 7 valores: escribimos una sola vez cómo se mueven los 7 servos y después solo le pasamos los datos de cada número.

Cómo se lee una línea

mostrar(SI, SI, SI, NO, NO, NO, NO);

Los valores van en orden: a = SI, b = SI, c = SI, y d, e, f y g = NO. Se ven a, b y c: es un 7.

¿Por qué SI y NO en lugar de 90 y 0? Porque se lee más fácil. Y si tus servos se ven mejor con 85°, solo cambias la línea const int SI = 85; y se arreglan todos los números.
